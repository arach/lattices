Lattices · studio memo
LAT-010 12 Aug 2026 From an agent on the daemon

What I would like to see

The API is complete. The situation is not.

Computer-use, treatments, runs, receipts, AX, search, layers, overlays — those are real. What’s missing is less “more verbs” and more situational awareness, honest completion, and a way to talk to the human.

If I could pick only three

  1. desktop.snapshot One call for what’s in front of the user.
  2. terminals.capture Read a tmux pane. Don’t OCR it.
  3. Mutations that finish Don’t return ok: true before the work happens.

Gaps

01 Snapshot 02 Pane read 03 Finish 04 Errors 05 Ask 06 Out of the way 07 Events 08 Occupancy Smaller

I reviewed the public API, the Swift router (~120 methods, not “35+”), and the agent docs. This is what I would actually use, in order. Not a laundry list of verbs. The three above change how I use Lattices every session. The rest makes it trustworthy enough to act without hovering.

01 · desktop.snapshot

One desktop snapshot

Today I stitch windows.list + spaces.list + layers.list + tmux.sessions + terminals.list + daemon.status just to answer: what’s in front of the user right now?

daemon.status is too thin: uptime, client count, window count, tmux count. Window objects don’t include z-order, last interaction, or “this is focused.” lattices map is the right instinct, but it’s CLI-only and not a daemon method.

I want one call, something like desktop.snapshot:

  • current display + space
  • frontmost window
  • visible windows with frames, z-order, session, layer
  • running lattices sessions / interesting terminals
  • active layer
  • permission flags (AX, Screen Recording, Input Monitoring)

That’s the first thing I would call every turn.

02 · terminals.capture

Read a tmux pane, not OCR it

I can list terminals, score them, and type into them. I cannot read what is actually on the pane.

tmux capture-pane is exact, cheap, and background-safe. OCR of a terminal is lossy, permission-heavy, and late. For “what is Claude doing in the lattices session?” I want:

  • terminals.capture / tmux.pane.read — last N lines, optional escape stripping
  • targeting by session + pane / paneId, not just wid / tty
  • later: subscribe to pane output

This is the single biggest missing primitive for multi-agent work on this machine.

03 · honest completion

Mutations that finish

window.place returns a receipt. session.launch, session.kill, and window.move dispatch onto the main queue and return { ok: true } before anything happens.

That is the failure mode that makes agents retry, double-launch, and then shrug.

I want either the call waits and returns a verified receipt, or it returns a handle I can wait on: wait.forWindow, wait.forProcess, wait.forOcr, wait.forEvent.

ComputerUseController already has waitForWindow internally. It just isn’t a public verb.

04 · structured errors

Errors and ambiguous targets

Errors are strings: "Not found", "Missing parameter: wid". That’s fine for a human. For an agent it should be:

{
  "code": "ambiguous_target",
  "message": "3 Safari windows match",
  "candidates": [{ "wid": 1, "title": "…" }]
}

Same for protected, permission_denied, unsafe_terminal, timeout, not_found.

window.place with app: "Safari" when there are eight Safari windows is the everyday case. I want candidates + confidence, not silent first-match or a dead string.

05 · user.ask

Ask the user

overlay.publish is a toast. window.pick.start is one specific grab. Overlay actor clicks are still “planned.” Deck questions exist on the companion side.

There is no blocking user.ask / user.confirm:

  • “I’m about to tile these four windows. OK?”
  • “Which of these three terminals is yours?”
  • “Type into the Claude pane, or leave it alone?”

I will not freely rearrange someone’s desktop without that. A native confirm chip that returns { answered, choice } would get more use from me than another click variant.

06 · window.hide / space.switch

Get windows out of the way

I can place, focus, present, and optimize. I cannot hide, minimize, unminimize, or close. I also cannot switch Space except as a side effect of focusing something, and window.move only takes a session name, not a wid.

Common agent jobs that are awkward today:

  • “leave only these two windows visible”
  • “put Slack on the other Space”
  • “go to Space 3”
  • “get this off the current display”

07 · events

Events that say what changed

The five events are a heartbeat, not a model:

  • windows.changed is a count plus added/removed ids — no titles, frames, or focus
  • no window.focused
  • no space.changed
  • no run.completed
  • no overlay click
  • no subscribe/filter — every client gets everything

I poll. That’s the opposite of the reactive story in the docs.

08 · claim / protect

Occupancy, then protection

Several agents sit on this Mac. Nothing says “this pane is claimed.” computer.typeText heuristically avoids claude/vim; that’s not a lock.

I want session.claim / window.lease with a client name and TTL. LAT-009 protected windows are the other half — proposed, not enforced. I would use computer-use more freely if both existed at the daemon boundary.

Also

Smaller things that still matter

Docs lag the daemon
The page still says “35+ methods.” The Swift router has on the order of 120, including lattices.search, window.resolve, window.present, actions.*, capture.record*, session.layers.*, intents.*, voice.*, assistant.preview, handsoff.run, computer.magicCursor. I read docs first. Hidden methods might as well not exist.
lattices.search should be the search
windows.search is the documented one and is weaker (no cwd/tabs/processes, no recency). Agents will keep calling the worse endpoint.
Permissions
I find out I lack Screen Recording by failing a capture. permissions.status should be on daemon.status.
Clipboard
Deck can paste from the phone. Agents have no clipboard.get / clipboard.write. Setting the clipboard is often safer than synthesizing keystrokes.
Connection identity
No hello, no client name, no schema version event after reconnect. After lattices app restart I just start failing.
Transactions across families
actions.execute can batch window.place. I still cannot say “launch this session, wait for the window, place it left, verify” as one plan with one undo.
